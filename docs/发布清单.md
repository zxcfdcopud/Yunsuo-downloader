## 一、推送源码

在仓库根目录（`F:\下载器工程`）执行：

```powershell
# 1) 初始化（如果还没有 .git）
git init
git branch -M main

# 2) 关联远程
git remote add origin https://github.com/zxcfdcopud/Yunsuo-downloader.git

# 3) 先看看会提交什么（确认没有 bin/obj/artifacts/tools 里的 exe）
git add -A
git status --short

# 4) 提交并推送
git commit -m "云梭下载器 v1.0.0：首个公开版本"
git push -u origin main
```

> `.gitignore` 已经排除 `bin/`、`obj/`、`artifacts/`、`tools/*.exe`，
> 所以推上去的只有源码 + 插件 + 文档 + 脚本，体积很小。

如果 GitHub 上建仓库时勾选了 README / .gitignore / LICENSE，
先删掉远程那些文件或改用 `git push --force`（**谨慎**，会覆盖远程）。

## 二、创建 Release（这一步决定「检查更新」能否工作）

程序读的是这个接口：

```
https://api.github.com/repos/zxcfdcopud/Yunsuo-downloader/releases/latest
```

所以必须发一个**正式 Release**（不能只是 tag），并且：

### 1) Tag 名必须是版本号

用 **`v1.0.0`**（程序会自动去掉开头的 `v`）。

### 2) 上传安装包附件

把下面这个文件上传为 Release 的附件（asset）：

```
artifacts\YunsuoDownloader-Setup-1.0.0.exe
```

程序会从 `assets` 里挑一个文件名匹配 `setup` 且以 `.exe` 结尾的作为下载地址。
建议就保持 `YunsuoDownloader-Setup-1.0.0.exe` 这个名字。

### 3) 填 Release 说明

Release 的正文（body）会原样显示在程序的「检查更新」对话框里。
建议直接用 `CHANGELOG.md` 里 v1.0.0 那段。

### 4) 发布后自测

```powershell
# 用命令行验证更新源能读到
.\artifacts\publish\ysd.exe update
```

正常应该看到"当前版本 1.0.0 / 已是最新版本"之类的输出。
如果看到「暂时查不到更新信息」，先确认 Release 是 **Published** 状态而不是 Draft。
